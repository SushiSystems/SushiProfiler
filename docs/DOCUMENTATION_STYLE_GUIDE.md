# Documentation style guide

Prose in this repository follows the `humanizer` skill of SushiSkills; where a document goes
follows the `documentation` skill. This page holds what is particular to SushiProfiler.

| Page | Speaks to | Register |
| --- | --- | --- |
| `README.md` at the root | Someone deciding whether to use SushiProfiler | What it is, the commands |
| `getting_started/` | Someone building or testing SushiProfiler | Second person, commands in order |
| `architecture/` | Someone changing the structure | Present tense, the code as it is |
| A module README | Someone changing the module | Present tense, the code as it is |

A command is written as `sp` spells it. A cited file is a path from the repository root in
backticks. English, British spelling in prose; identifiers keep the code's spelling. A name that
exists in the design only is written in the design document, never in the manual.
